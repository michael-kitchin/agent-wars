# How to Play: Quick Reference, New Features, and Screenshots

> **For agentic workers:** Implement this plan phase by phase, in order. Steps use checkbox (`- [ ]`) syntax. Do not commit or push. Do not copy phase names, step numbers, or any other identifier from this file into code, comments, configuration, test names, lint text, or `doc/`.

**Goal:** Make `doc/how-to-play.md` a quick reference for grand-strategy players. It gains a Units at a Glance table, short how-tos for saving and loading, ballistic missiles, fortifications, and credits and hiring, and screenshots regenerated by a script.

**Architecture:** A new CommonJS script, `scripts/doc-shots/`, drives the built Electron app with `playwright-core`, the same way `scripts/ui-smoke/` does. It reuses that harness's launch, map, and new-game helpers. It writes PNGs straight into `doc/media/`. A capture is written to a temporary file and copied over the old file only after it succeeds. On Windows, renaming over an existing file can fail, so the copy is `fs.copyFileSync`. A failed capture never touches the old file. Unit-token images are drawn on a page canvas from the app's own glyph files and palette. The guide is reorganized first, then gains the table and sections.

**Tech stack:** Node CommonJS scripts, `playwright-core` 1.62 (`_electron`), `h3-js`, Electron 40, `node:test`, and Markdown.

**Spec:** This file is the spec.

## Global Constraints

- Do not commit or push. Use `git restore doc/media/<file>` to put back an old image when a new capture is wrong.
- Keep plan identifiers out of code, comments, docs, and configuration (`.cursor/rules/12-no-plan-identifiers.mdc`).
- Script files and folders under `scripts/` are kebab-case `.cjs` (`doc/naming-conventions-contract-v1.md`, `scripts/*.cjs` row).
- Every new or changed function and module-level constant gets an orienting comment in the shape `scripts/ui-smoke/` already uses: Purpose, When to use, Expected outcome, and Exceptions.
- Use `const` and `Object.freeze` for constants. Functions take at most 6 named arguments. Use an options object beyond that.
- Each new file stays under 600 lines.
- Add no new npm dependency. `playwright-core` and `h3-js` are already installed. If one turns out to be necessary, update `THIRD-PARTY-NOTICES.md` in the same change.
- Player-facing symbols: production is `⚒︎` (U+2692 U+FE0E, `PRODUCTION_CAPACITY_SYMBOL` in `src/shared/economySymbols.ts`), and credits are `¤` (U+00A4, `CREDITS_SYMBOL`). Ranges use an en dash (`8–60`). Never use an em dash.
- Headings in `doc/how-to-play.md` use title case (house style). GitHub anchors are lowercase, so a capitalization-only change does not move a link. A renamed heading does, and the link checker in phase 6 must pass before that phase ends.
- Leave historical docs and `.spec/completed/` alone.
- Hiring follows the current code, which `doc/how-to-play.md` and `doc/ux/build-popup.md` already describe. Placing a raise or rehire takes its fee from the treasury at once (`spendTreasuryCredits` in `src/main/gameActions/hireOrders.ts`). Removing the order returns the fee, and any count the end of the turn can't fill is refunded. The top bar turns short only when the balance is below this turn's upkeep. The type list, count, and Hire button appear only when one unit fits both the production still left and the treasury (`oneUnitRaiseShortage` returns null). When none fits, the panel shows one of `All credits allocated.`, `All production capacity allocated.`, or `All credits and production capacity allocated.`, and those controls stay hidden. A click whose count does not fit shows one of `Not enough credits.`, `Not enough production capacity.`, or `Not enough credits or production capacity.`, and does not add the order. A mercenary token shows `¤` (`CREDITS_SYMBOL`) at its center, not `$`, in `MERCENARY_BADGE_FONT` (`bold 14px system-ui, sans-serif`). The top-bar upkeep suffix is ` + ¤M/turn` (`formatCreditsUpkeepSuffix`), so the line reads `¤N + ¤M/turn`. Production is `⚒N` with no leading plus. Keep these sentences when moving or trimming. Never bring back the older wording that an order doesn't check the balance, that it is charged only when it fills, that the mark is `$`, that the badge is 11px or sits below the token, that a hidden raise row says "Not enough…", that the suffix is a minus (`−¤N/turn`), or that Production starts with `+`.

## Decisions Already Made

- **Output:** images go straight into `doc/media/`. The git diff is the review.
- **Stale over missing:** a failed or skipped capture never deletes or blanks an existing image. A map shot taken before any map tile loads is skipped, not written.
- **Screenshot scope:** the script writes new images for the new sections and the unit tokens. It also regenerates these stale images under the same names: `global-preview.png`, `regional-preview.png`, `stack-select-1.png`, `stack-select-2.png`, `movement-planning-1.png`, `movement-planning-2.png`, `ranged-attack-1.png`, `ranged-attack-2.png`, `air-strike.png`, and `unit-building.png`. These stay untouched: `message-popup.png` and `colombia-battle-taunt.png` (they need a live model), `status-popup.png`, `sealift.png`, `tactical-battle-dialog.png`, the two `unit-*` tooltip images, the three road, rail, and terrain images, the `front-page-*` images, and the charts.
- **Units table shape:** four columns, Token, Unit, Global game, and Regional game. The rows are infantry, armor, naval, air, missile, mercenary, fortification, and Credits. Attack and defense go in the Unit cell. Regional cells show the lowest and highest value across the 23 regional maps.
- **Trimming:** move and shorten text freely. Cut detail aimed at implementers (CSS variables, code symbols, pixel offsets, exact sentence templates), and link to the `doc/ux/` page or `combat-rules-v3.md` that already holds it. Never cut a rule a player needs.
- **Native dialogs:** Save and Load open operating-system dialogs. The script never clicks Save or Load into a native dialog. It photographs the menu and the in-app confirm dialog only.
- **Device scale:** the script launches Electron with `--force-device-scale-factor=1`, so the image pixels equal the CSS clip size.

### Phase 2: Script Skeleton, Capture Helpers, and Token Images

**Files:** Create `doc-shots.cjs`, `doc-shots-capture.cjs`, `doc-shots-capture.test.cjs`, and `doc-shots-tokens.cjs`. Modify `package.json` and `scripts/run-main-node-tests.cjs`.

**Produces (`doc-shots-capture.cjs`):**
- `MEDIA_DIR`, which is `path.join(REPO_ROOT, 'doc', 'media')`.
- `unionClip({ boxes, pad, viewport })`, a pure function. It takes `{x, y, width, height}` boxes, pads their union, rounds outward to whole pixels, and clamps the result to `0..viewport.w` and `0..viewport.h`. It throws when `boxes` is empty or the clamped area is zero.
- `clipAround(page, { selectors = [], points = [], pad = 16, viewport })`. It reads each selector's `boundingBox()` and throws, naming the selector, when one is not visible. Each point becomes a 1×1 box. A point whose x is outside `0..viewport.w` or whose y is outside `0..viewport.h` throws `point is off screen`, so a cropped sliver is never written over an existing image. It returns `unionClip`.
- `pngSize(buffer)`, which returns `{ width, height }` from the IHDR chunk (big-endian at byte offsets 16 and 20). It throws when the 8-byte PNG signature is missing.
- `writeFileAtomic(finalPath, buffer)`. It writes `${finalPath}.tmp`, copies that file onto `finalPath` with `fs.copyFileSync` (this replaces an existing file on Windows, where `fs.renameSync` can fail), then deletes the temporary file. On error it deletes the temporary file and rethrows. It does not delete `finalPath` first.
- `runShot(report, fileName, captureFn)`. It awaits `captureFn()`, which returns a PNG `Buffer`. On success it writes the file, pushes `{ fileName, width, height }` to `report.written`, and prints `WROTE doc/media/<file> <w>x<h>`. On a throw it pushes `{ fileName, reason }` to `report.skipped`, prints `SKIP <file> :: <reason>`, and leaves the file alone. It never throws.
- `waitForMapTiles(page, timeoutMs = 20000)`. The map uses a Leaflet raster `tileLayer` (`src/renderer/map/worldLeafletMap.ts`). It resolves once `.leaflet-tile-loaded` exists, or an `img.leaflet-tile` has `naturalWidth > 0`. Otherwise it throws `map tiles did not load`.

**Produces (`doc-shots-tokens.cjs`):** `writeTokenImages(page, report)`. It writes `token-infantry.png`, `token-armor.png`, `token-naval.png`, `token-air.png`, `token-missile.png`, `token-mercenary.png`, and `token-fortification.png`, each 48×48 with a transparent background.

### Phase 5: Economy and Missile Screenshots, Second Session

**Files:** Create `doc-shots-edits.cjs`, `doc-shots-edits.test.cjs`, and `doc-shots-economy.cjs`. Add the test to `scripts/run-main-node-tests.cjs`. Add three map helpers to `scripts/ui-smoke/ui-smoke-map.cjs`.

**Consumes:** `editSavedMatch` from `ui-smoke-session.cjs`, and the state `writeOrderShots` returned. The edit SQL matches `src/main/gameDb/schema.ts`. Do not wait for production to spawn a missile or a fortification. The smoke scenario cannot be relied on to have an Advanced city, and a missile spawned on a city hex would share that hex with other units, so it could not be selected alone.

**Produces (`doc-shots-edits.cjs`, all pure):** `humanSeatId(state)` and `economyEdit(state, rules)`.

`humanSeatId` is the active human seat's `seatId`, using the same rule as `marchDestinations` in `ui-smoke-map.cjs`. Throw when there is none. `rules` is `GLOBAL_GAME_MAP.rules` from `dist/shared/activeGameMap.js`.

`economyEdit` reads only these fields: `seats` (`seatId`, `kind`, `outTurn`), `homeRegionHexesBySeat`, `strategicInfrastructure` (`h3Index`, `urbanHexCount`), `hexes` (`h3Index`, `terrainKind`), `units` (`id`, `player`, `unitType`, `h3Index`, `embarkedOnNavalUnitId`), and `pendingOrders` (`toH3Index`). A lone unit is a human unit whose hex holds no other unit, the same rule as `loneHumanUnits`. A land hex is one whose `terrainKind` is not `water`. Coastal counts as land.

`economyEdit` returns `{ queueHex, fortHex, missileHex, launchHoverHex, enemyHex, armorId, armorHex, showMissile, raiseFits, statements }`. Choose the hexes in this order, and keep them distinct. Throw only when the seat, the second city, the armor, its land neighbor, or the missile stand is missing. A city too small to show a missile, or too small to raise, is not a throw: one throw skips all six second-session shots, including ones that do not need that city.

- `queueHex` is a human home hex. Prefer one whose `urbanHexCount` is at least `rules.advancedMinUrbanCells` (21 on the global map), and among those pick the largest. When none is that large, pick the largest anyway. `showMissile` is true only in the first case. The build popup's type list comes from `getAvailableBuildUnitTypes` (`src/main/productionRules.ts`). A stored `missile` row is not a choice on a smaller city, and the select then shows a different type. `raiseFits` is true when `urbanHexCount * MERCENARY_RAISE_CAPACITY_MULTIPLIER` is at least `rules.infantryCost`. Require that multiplier from `dist/shared/mercenaryRules.js`. Do not hard-code 2.
- `fortHex` is a different human home hex with `urbanHexCount` at least 1, the smallest such hex. Throw when none exists.
- `armorId` and `armorHex` are the first lone human armor that is not standing on `queueHex` or `fortHex`. `enemyHex` is an empty land neighbor of `armorHex`, not `queueHex` or `fortHex`, and not any `pendingOrders[].toH3Index`. The march left by the first session is in that list.
